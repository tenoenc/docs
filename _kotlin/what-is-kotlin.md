## 코틀린이란?

코틀린은 자바 플랫폼에서 돌아가는 새로운 프로그래밍 언어다. 간결하고, 실용적이며, 자바 코드의 상호운용성을 중시한다.

### 코틀린의 주요 특성

#### 1. 대상 플랫폼은 자바가 실행되는 곳이다

코틀린의 주목적은 현재 자바가 사용되고 있는 모든 용도에 적합하면서도 더 간결하고 생산적이며 안전한 대체 언어를 제공하는 것이다. 자바가 사용되는 많은 환경에 코틀린을 도입하면 **더 적은 코드로 더 편하게** 프로그래머의 목표를 달성할 수 있다.

**다수의 환경에서 실행 가능**

코틀린을 활용할 수 있는 가장 일반적인 영역은 웹 애플리케이션 서버, 안드로이드 정도지만, 다른 환경에서도 잘 작동한다. 예를 들어, 인텔 멀티OS 엔진을 사용하면 iOS 디바이스에서 실행할 수 있고, 토네이도FX, 자바 FX 등을 함께 사용하면 데스크탑 애플리케이션을 작성할 수 있다.

**자바스크립트로 컴파일 가능**

코틀린은 자바뿐만 아니라 자바스크립트로도 컴파일할 수 있다. 따라서, 코틀린 코드를 브라우저나 노드에서 실행할 수 있다.

#### 2. 정적 타입 지정 언어

자바와 마찬가지로 코틀린도 정적 타입 지정 언어다.

> 정적 타입 지정: 모든 프로그램 구성 요소의 타입을 **컴파일 시점에** 알 수 있고 프로그램 안에서 객체의 필드나 메소드를 **사용할 때마다** 컴파일러가 **타입을 검증**한다.
{: .block-tip }

**타입 추론**

자바와 달리 코틀린에서는 모든 변수의 타입을 프로그래머가 직접 명시할 필요가 없다. 대부분의 경우 **코틀린 컴파일러가** 문맥으로부터 변수 타입을 **자동으로 유추**할 수 있기 때문에 프로그래머는 타입 선언을 생략해도 된다.

**정적 타입 지정 언어의 장점**

실행 시점에 어떤 메서드를 호출할지 알아내는 과정이 필요 없어서 빠르고(**성능**), 컴파일러가 정확성을 검증하기 때문에 예기치 않은 오류가 더 적고(**신뢰성**), 객체의 타입을 미리 알기 때문에 다루기 쉽고(**유지 보수성**), 이 때문에 도구에서 유용한 기능을 더 잘 만들 수 있다(**도구 지원**).

**Nullable 타입 지원**

널이 될 수 있는 타입을 지원함에 따라 컴파일 시점에 널 포인터 예외가 발생할 수 있는지 여부를 컴파일러가 검사할 수 있어 프로그램의 신뢰성을 높일 수 있다.

#### 3. 함수형 프로그래밍과 객체지향 프로그래밍

**함수형 프로그램의 핵심 개념**

- **일급 시민 함수**: 함수를 일반 값처럼 다룬다. 함수를 변수에 저장할 수 있고, 함수를 인자로 다른 함수에 전달할 수 있으며, 함수에서 새로운 함수를 만들어서 반환할 수 있다.
- **불변성**: 일단 만들어지고 나면 내부 상태가 절대로 바뀌지 않는 불변 객체를 사용해 프로그램을 작성한다.
- **부수 효과 없음**: 입력이 같으면 항상 같은 출력을 내놓는다. 또한, 다른 객체의 상태를 변경하지 않으며, 함수 외부나 다른 바깥 환경과 상호작용하지 않는 순수 함수를 사용한다.

**이 핵심 개념을 사용하는 프로그램을 작성하면 뭐가 좋을까?**

첫째로 **간결하다**. 함수를 값처럼 사용하면 추상화가 더 강력해지고 이에 따라 코드 중복을 막을 수 있다. 두 번째로 **Thread-Safe하다**. 불변 데이터 구조를 사용하기 때문에 같은 데이터를 여러 스레드가 변경할 수 없다. 세 번째로 **테스트하기 쉽다**. 부수 효과가 없기 때문에 준비 코드 없이 독립적으로 테스트할 수 있다.

**코틀린은 함수형을 강제하지 않음**

코틀린으로 코드를 작성할 때는 객체지향과 함수형 접근 방법을 함께 조합해서 문제에 가장 적합한 도구를 사용하면 된다.

#### 4. 무료 오픈소스

코틀린과 관련된 모든 도구는 오픈소스이며, 어떤 목적에든 무료로 사용할 수 있다. 코틀린은 Apache 2 라이선스하에 제공된다.
