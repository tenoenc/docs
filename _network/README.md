## 네트워크 아키텍처

네트워크 아키텍처는 단순히 컴퓨터를 연결하는 물리적 연결망을 넘어, 데이터라는 무형의 정보가 물리적 신호로 변환되어 전 세계를 유동하는 과정 전체를 관장하는 거대한 설계 프레임워크입니다. 엔지니어링 관점에서 아키텍처의 존재 이유는 '상호 운용성(Interoperability)'과 '관심사의 분리(Separation of Concerns)'에 있습니다. 서로 다른 벤더가 제작한 하드웨어와 다양한 운영체제 위에서 동작하는 소프트웨어가 충돌 없이 대화하기 위해서는, 데이터를 처리하는 각 단계가 엄격하게 정의된 규격에 따라 모듈화되어야 합니다. 이러한 구조적 계층화는 특정 계층의 기술적 변화가 전체 시스템의 붕괴로 이어지지 않도록 보호하는 절연체 역할을 수행합니다. 예를 들어, 하위의 광케이블이 구리선으로 교체되더라도 상위의 HTTP 프로토콜은 그 변화를 인지하지 못한 채 동일한 로직으로 동작할 수 있는 것은 아키텍처가 제공하는 추상화의 힘입니다.

### 계층 참조 모델 (Reference Models)

참조 모델은 네트워크 통신의 복잡성을 인지 가능한 수준으로 분해하기 위한 논리적 지도입니다. 초기 네트워크는 제조사마다 독자적인 통신 규격을 사용하여 폐쇄적인 생태계를 형성했으나, 이는 확장성의 치명적인 병목이 되었습니다. 참조 모델은 통신 과정을 기능적 단위로 쪼개어 각 단위가 수행해야 할 책임과 인접 계층과의 인터페이스 규칙을 명시합니다. 이를 통해 네트워크 장비 개발자는 하드웨어 가속에 집중하고, 애플리케이션 개발자는 소켓 추상화 너머의 복잡한 비트 전송 과정을 고민하지 않아도 되는 분업 시스템을 구축했습니다. 하지만 이러한 계층화는 필연적으로 데이터의 앞뒤에 제어 정보를 덧붙이는 '오버헤드'를 발생시키며, 각 계층을 통과할 때마다 발생하는 '컨텍스트 스위칭' 비용과 지연 시간(Latency)이라는 엔지니어링적 트레이드오프를 수반합니다.

#### OSI 7계층 모델

ISO(국제표준화기구)가 제정한 OSI(Open Systems Interconnection) 7계층 모델은 네트워크 통신의 표준적 철학을 제시하는 가장 정교한 참조 모델입니다. 실제 인터넷의 주류인 TCP/IP 모델보다 세분화된 구조를 가진 이 모델은 교육적 가치뿐만 아니라, 네트워크 트러블슈팅의 표준 가이드라인으로 기능합니다. 엔지니어는 "L2 문제인가, L3 문제인가?"라는 질문을 통해 문제의 범위를 물리적 링크의 오류(L2)인지, 경로 배정의 오류(L3)인지 즉각적으로 판별합니다. 각 계층은 하위 계층으로부터 서비스를 제공받고 상위 계층으로 서비스를 제공하는 수직적 관계를 형성하며, 동일 계층끼리는 논리적으로 직접 연결된 것처럼 통신하는 수평적 피어 투 피어(Peer-to-Peer) 논리를 유지합니다.

##### 물리 계층 (Physical)

물리 계층은 데이터 전송의 최하단에서 디지털 비트(0과 1)를 전기적, 광학적, 또는 전파 신호로 변환하여 실제 매체로 송출하는 물리적 인터페이스 전체를 관장합니다. 이 계층의 본질은 하드웨어 그 자체이며, 전압의 레벨, 신호의 타이밍, 커넥터의 핀 배치, 광케이블의 파장 등 물리적 특성을 엄격히 규정합니다.

엔지니어링의 심부에서는 SerDes(Serializer/Deserializer) 칩이 병렬 데이터를 직렬 신호로 압축하여 고속 전송을 가능케 하며, 이 과정에서 발생하는 신호 감쇄(Attenuation)와 왜곡(Distortion)을 극복하기 위한 복잡한 인코딩 기법이 동원됩니다. 예를 들어, 단순한 전압의 유무로 0과 1을 구분하는 NRZ(Non-Return to Zero) 방식부터, 신호의 진폭을 4단계로 나누어 한 번에 2비트를 전송하는 PAM4(Pulse Amplitude Modulation 4-level) 방식에 이르기까지, 물리 계층은 제한된 대역폭 내에서 전송 효율을 극대화하기 위해 물리 법칙과 치열한 싸움을 벌입니다.

> **물리 계층의 하드웨어 추상화**
> 
> 물리 계층은 상위 계층의 데이터가 '무엇'인지는 전혀 상관하지 않습니다. 오직 매체로 유입되는 '비트의 흐름(Bitstream)'을 오류 없이 반대편 NIC(Network Interface Card)의 물리 회로까지 도달시키는 것에만 집중합니다. 이때 발생하는 전파 지연(Propagation Delay)은 빛의 속도라는 물리적 한계에 종속되며, 이는 소프트웨어 최적화로 해결할 수 없는 영역입니다.

##### 데이터 링크 계층 (Data Link)

데이터 링크 계층은 물리 계층의 신뢰할 수 없는 비트 전송 위에 '노드 대 노드(Node-to-Node)' 간의 신뢰성 있는 전송 통로를 구축하는 역할을 합니다. 물리 계층이 단순히 전선 위로 신호를 쏘는 것이라면, 데이터 링크 계층은 그 신호의 시작과 끝을 구분하여 '프레임(Frame)'이라는 의미 있는 단위로 묶는 '프레이밍(Framing)' 작업을 수행합니다.

이 계층의 핵심은 MAC(Media Access Control) 주소를 기반으로 물리적 인접 장치들 사이에서 누가 언제 데이터를 보낼지 결정하는 매체 접근 제어와, 수신된 프레임이 전송 과정에서 훼손되지 않았는지 검증하는 오류 검출 메커니즘에 있습니다. 하드웨어 레벨에서 계산되는 CRC(Cyclic Redundancy Check)는 프레임의 꼬리(Trailer)에 붙어 비트 반전 오류를 탐지하며, 만약 오류가 발견되면 해당 프레임은 즉시 폐기(Drop)됩니다. 이 계층은 브리지나 스위치와 같은 장비가 작동하는 영역으로, 물리적 링크의 토폴로지를 관리하고 흐름 제어(Flow Control)를 통해 수신측의 처리 능력을 넘어서는 데이터 폭주를 방지합니다.

> **L1과 L2의 경계: NIC의 내부 로직**
> 
> 운영체제의 커널 드라이버가 NIC에 데이터를 전달하면, NIC 내부의 컨트롤러는 데이터를 이더넷 프레임으로 캡슐화하고 MAC 주소를 부여합니다. 이후 물리적 트랜시버가 이를 전기 신호로 바꿉니다. 즉, 데이터 링크 계층은 소프트웨어(OS)와 하드웨어(전선)가 만나는 가장 치열한 접점입니다.

##### 네트워크 계층 (Network)

네트워크 계층은 데이터 링크 계층이 제공하는 '노드 대 노드' 전송 능력을 확장하여, 서로 다른 네트워크 망에 존재하는 '호스트 대 호스트(Host-to-Host)' 간의 논리적 통로를 개척합니다. 이 계층의 가장 원대한 목표는 수많은 네트워크가 얽힌 복잡한 경로 사이에서 목적지까지 도달하는 최적의 경로를 찾아내는 '라우팅(Routing)'입니다. L2가 물리적인 하드웨어 주소(MAC)에 의존한다면, L3는 전 세계적으로 고유한 논리적 주소 체계인 IP(Internet Protocol)를 사용하여 논리적 토폴로지를 구축합니다.

이 계층의 전송 단위인 '패킷(Packet)'에는 목적지 IP 주소와 함께 TTL(Time To Live) 값이 포함됩니다. 라우터를 통과할 때마다 1씩 감소하는 TTL은 패킷이 네트워크 루프에 빠져 영원히 순환하며 대역폭을 고갈시키는 것을 방지하는 최종 안전장치입니다. 또한, 네트워크 계층은 하위 계층의 전송 규격에 따라 패킷을 더 작은 단위로 쪼개는 '단편화(Fragmentation)'와 수신 측에서의 '재조합(Reassembly)' 기능을 수행하며, 이는 MTU(Maximum Transmission Unit)라는 하드웨어적 한계치와 소프트웨어적 로직이 충돌하는 지점에서 발생합니다.

> **라우팅 테이블의 비용과 성능**
> 
> 라우터는 패킷을 받을 때마다 커널 내의 라우팅 테이블을 조회합니다. 이때 '가장 긴 일치 접두사(Longest Prefix Match)' 알고리즘을 사용하는데, 테이블의 크기가 커질수록 CPU 연산 비용이 기하급수적으로 증가합니다. 이를 해결하기 위해 현대의 고성능 라우터는 ASIC(Application Specific Integrated Circuit) 기반의 하드웨어 가속을 통해 메모리 조회 속도를 극대화합니다.
{: .block-tip }

##### 전송 계층 (Transport)

전송 계층은 하부 네트워크 망의 신뢰성이나 품질에 관계없이, 양 끝단의 사용자(프로세스) 간에 오류 없고 신뢰할 수 있는 데이터 전송을 보장하는 핵심 계층입니다. L3가 장치와 장치 사이의 배달을 책임진다면, 전송 계층은 그 장치 안에서 실행 중인 구체적인 '프로세스(Process)'로 데이터를 전달하는 책임을 집니다. 이를 위해 '포트(Port) 번호'라는 식별자를 도입하여 데이터의 역다중화(Demultiplexing)를 수행합니다.

이 계층의 정점인 TCP(Transmission Control Protocol)는 가상 회선을 설정하여 데이터의 순서를 보장하고, 유실된 데이터를 재전송하며, 네트워크 혼잡 상황에 따라 전송 속도를 조절하는 고도로 복잡한 알고리즘의 집합체입니다. 반면 UDP(User Datagram Protocol)는 이러한 제어 기능을 완전히 제거하여 오버헤드를 최소화하고 지연 시간을 극도로 낮추는 전략을 취합니다. 전송 계층은 상위 계층으로부터 받은 긴 메시지를 '세그먼트(Segment)' 단위로 분할하고 순서 번호(Sequence Number)를 부여하여, 수신 측에서 데이터가 섞이거나 누락되지 않도록 관리합니다.

##### 세션 계층 (Session)

세션 계층은 응용 프로그램 간의 통신 시나리오를 관리합니다. 단순히 데이터를 주고받는 단계를 넘어, 통신 장치들 사이의 '대화(Dialogue)'를 설정, 유지, 그리고 종료하는 메커니즘을 정의합니다. 세션 계층의 핵심 키워드는 '동기화(Synchronization)'입니다. 대용량 데이터 전송 중에 통신이 끊겼을 때 처음부터 다시 전송하는 낭비를 막기 위해 체크포인트(Checkpoint)를 삽입하여 복구 지점을 제공합니다.

현대 인터넷 아키텍처에서는 세션 계층의 기능이 전송 계층(TCP Connection)이나 응용 계층(HTTP Session/Cookie)으로 흡수되어 독립적인 프로토콜로 구현되는 경우는 드물지만, 원격 프로시저 호출(RPC)이나 SQL 세션 관리와 같은 논리적 개념 속에서 여전히 중요한 설계 원칙으로 작용합니다. 이 계층은 통신 방식이 단방향(Simplex)인지, 반이중(Half Duplex)인지, 전이중(Full Duplex)인지 결정하는 제어권 또한 가집니다.

##### 표현 계층 (Presentation)

표현 계층은 데이터의 '구문(Syntax)'과 '의미(Semantics)'에 집중합니다. 서로 다른 기종의 컴퓨터가 각기 다른 데이터 인코딩 방식(예: ASCII vs EBCDIC)을 사용하더라도, 데이터를 공통의 형식으로 변환하여 상호 소통이 가능하게 만듭니다. 또한 네트워크 전송 효율을 높이기 위한 데이터 압축과, 정보의 보안을 위한 암호화(Encryption) 및 복호화가 이 계층의 주된 임무입니다.

오늘날 웹 환경에서 자주 사용되는 JSON, XML 같은 데이터 직렬화 포맷이나, SSL/TLS를 통한 전송 보안 프로토콜의 일부 기능이 표현 계층의 철학을 계승하고 있습니다. 이 계층이 존재함으로써 응용 프로그램은 데이터가 네트워크를 통해 전달되는 동안 어떤 추상적 형태로 변환되는지 신경 쓰지 않고 자신의 비즈니스 로직에만 집중할 수 있습니다.

##### 응용 계층 (Application)

응용 계층은 사용자 인터페이스와 네트워크 서비스가 직접적으로 만나는 최상위 계층입니다. 사용자가 브라우저에 URL을 입력하거나 이메일을 보낼 때, 그 의도를 네트워크 프로토콜 언어로 변환하는 역할을 합니다. HTTP, DNS, FTP, SMTP 등 우리가 일상적으로 접하는 거의 모든 네트워크 서비스 프로토콜이 이 계층에 해당합니다.

응용 계층 프로토콜은 데이터의 내용 그 자체를 다루며, 사용자 인증, 서비스 품질(QoS) 요구사항 정의 등을 수행합니다. 엔지니어링 관점에서 응용 계층은 가장 변화가 빠르고 복잡한 영역이며, 서비스의 성격에 따라 텍스트 기반의 가독성 높은 프로토콜(HTTP/1.1)부터 바이너리 기반의 고효율 프로토콜(HTTP/2, Protobuf)까지 다양한 설계적 선택지가 존재합니다.

#### TCP/IP 4계층 모델

OSI 7계층이 학술적이고 엄격한 분할을 강조한다면, TCP/IP 4계층 모델은 실무적이고 구현 중심적인 구조를 지향합니다. 인터넷의 폭발적인 성장과 함께 사실상의 표준(De-facto Standard)으로 자리 잡은 이 모델은 복잡한 7계층을 4개의 실용적인 층으로 압축했습니다. 하위의 물리 및 데이터 링크 계층은 '네트워크 액세스 계층'으로, 세션, 표현, 응용 계층은 하나로 통합된 '응용 계층'으로 정의함으로써 프로토콜 스택의 오버헤드를 줄이고 구현의 유연성을 확보했습니다.

> **OSI와 TCP/IP의 철학적 차이**
> 
> OSI 모델은 "모든 통신은 이 규격에 맞춰야 한다"는 Top-Down 방식의 접근인 반면, TCP/IP는 "실제로 작동하는 것을 계층화하자"는 Bottom-Up 방식에서 탄생했습니다. 이로 인해 TCP/IP는 계층 간 경계가 다소 모호한 경우가 있으나, 실제 인터넷 환경의 높은 변화 속도에 기민하게 대응할 수 있는 복원력을 갖게 되었습니다.
{: .block-warning }

##### 네트워크 액세스 계층 (Network Access Layer)

네트워크 액세스 계층은 TCP/IP 모델의 최하단에서 운영체제의 네트워크 드라이버와 실제 네트워크 인터페이스 카드(NIC) 사이의 인터랙션을 담당합니다. OSI 모델의 물리 계층과 데이터 링크 계층을 하나로 통합한 이 계층은, 데이터가 물리적인 매체를 통해 전기 신호나 광 신호로 전달되기 위한 모든 준비 과정을 수행합니다. 엔지니어링 측면에서 이 계층의 가장 큰 책임은 상위 계층인 인터넷 계층으로부터 내려온 IP 패킷을 '프레임(Frame)'으로 캡슐화하고, 네트워크 매체(Ethernet, Wi-Fi 등)의 특성에 맞게 신호를 송출하는 것입니다.

특히 현대 시스템에서는 프레임의 체크섬 계산이나 패킷 분할과 같은 작업을 CPU가 아닌 NIC 하드웨어가 직접 처리하는 'Checksum Offload'나 'Large Send Offload(LSO)' 기술이 이 계층에서 구현됩니다. 이는 커널의 부하를 줄여 전체 시스템의 처리량(Throughput)을 획기적으로 높이는 핵심 기법입니다. 그러나 이러한 하드웨어 가속은 특정 벤더의 드라이버 소프트웨어와 하드웨어 간의 밀접한 결합(Tight Coupling)을 야기하며, 이는 하위 레벨 디버깅 시 패킷 캡처 도구(tcpdump 등)에서 실제 전송되는 패킷과 캡처된 패킷의 크기가 다르게 보이는 현상과 같은 트레이드오프를 발생시킵니다.

##### 인터넷 계층 (Internet Layer)

인터넷 계층은 네트워크 액세스 계층 위에서 동작하며, 서로 다른 네트워크 망에 위치한 호스트 간의 경로 선택과 패킷 전달을 담당하는 인터넷의 중추입니다. OSI 모델의 네트워크 계층과 대응되며, IP(Internet Protocol)가 이 계층의 주인공입니다. 이 계층은 하부의 물리적 네트워크 구성이 이더넷인지, 광섬유인지, 혹은 무선 LAN인지에 관계없이 동일한 IP 주소 체계를 통해 전 세계의 모든 장치를 논리적으로 연결하는 '추상화 계층'으로서 존재합니다.

IP 프로토콜은 본질적으로 '최선형 서비스(Best-effort Delivery)'를 지향합니다. 즉, 패킷이 목적지에 정확히 도착했는지, 순서가 뒤바뀌지는 않았는지를 보장하지 않습니다. 이러한 '비연결형' 설계는 네트워크 중간 장치(라우터)들의 복잡도를 낮추어 전 세계 규모의 확장성을 확보할 수 있게 했습니다. 신뢰성이라는 무거운 책임은 상위 계층인 전송 계층으로 완벽히 넘기고, 인터넷 계층은 오직 패킷의 경로 최적화(Routing)에만 전념하도록 설계된 '엔드 투 엔드 원칙(End-to-End Principle)'의 정수를 보여줍니다.

> **인터넷 계층의 'Waist of the Hourglass' 구조**
> 
> 인터넷 프로토콜 스택을 모래시계 모양으로 시각화하면, 수많은 응용 프로그램(상단)과 다양한 물리 매체(하단)를 이어주는 가느다란 허리 부분에 단 하나의 프로토콜, IP가 존재합니다. 이 극단적인 단순화 덕분에 새로운 네트워크 하드웨어 기술이나 응용 프로그램이 등장해도 IP라는 공용어만 지원하면 인터넷에 즉시 통합될 수 있는 범용성을 갖게 되었습니다.
{: .block-tip }

##### 전송 계층 (Transport Layer)

전송 계층은 인터넷 계층이 제공하는 호스트 대 호스트 통신 위에 '프로세스 대 프로세스' 통신의 신뢰성을 부여합니다. 애플리케이션 개발자가 소켓(Socket) API를 통해 가장 빈번하게 상호작용하는 지점입니다. TCP/IP 모델에서의 전송 계층은 단순히 데이터를 전달하는 것을 넘어, 데이터의 흐름 제어(Flow Control), 오류 제어(Error Control), 그리고 혼잡 제어(Congestion Control)를 통해 통신 품질을 소프트웨어적으로 완성합니다.

특히 TCP의 경우, 커널 내부에 유지되는 'Transmission Control Block(TCB)'이라는 데이터 구조를 통해 연결 상태, 윈도우 크기, 타이머 정보 등을 정교하게 관리합니다. 이는 CPU와 메모리 자원을 지속적으로 소모하는 작업이며, 수만 개의 동시 접속을 처리하는 고성능 서버에서는 이 TCB 객체의 효율적인 할당과 회수가 시스템 성능의 핵심 병목이 되기도 합니다. 반면 UDP는 이러한 제어 오버헤드를 완전히 제거함으로써 하드웨어 성능을 한계까지 끌어올려야 하는 실시간 스트리밍이나 멀티캐스트 환경에서 독보적인 성능적 가치를 발휘합니다.

##### 응용 계층 (Application Layer)

TCP/IP 모델의 응용 계층은 OSI 모델의 세션, 표현, 응용 계층을 하나로 통합한 영역입니다. 이는 실제 소프트웨어 구현에서 세션 관리나 데이터 인코딩 로직이 별도의 독립된 계층이라기보다, 애플리케이션의 비즈니스 로직과 밀접하게 결합되어 구현된다는 엔지니어링적 현실을 반영한 결과입니다. HTTP, DNS, SMTP와 같은 프로토콜들은 단순히 데이터를 주고받는 규격을 넘어, 웹의 브라우징 경험이나 도메인 이름 해석과 같은 사용자 중심의 기능을 정의합니다.

응용 계층의 통합은 계층 간 데이터 이동 시 발생하는 불필요한 메모리 복사(Context Switching 및 Data Copying)를 줄여 성능상 이점을 제공합니다. 예를 들어, 보안을 위한 SSL/TLS 암호화는 OSI 관점에서는 표현 계층의 기능이지만, 실제로는 응용 계층의 데이터가 전송 계층으로 내려가기 직전에 라이브러리(OpenSSL 등) 형태로 처리됩니다. 이러한 실용적인 통합은 프로토콜 스택의 유연성을 높였으나, 개발자가 세션 유지나 캐릭터셋 변환과 같은 세밀한 통신 제어 기능을 애플리케이션 레벨에서 직접 설계해야 한다는 책임의 무게를 수반합니다.

### 데이터 전송 매커니즘 (Transmission)

데이터 전송은 단순히 신호를 보내는 행위를 넘어, 복잡한 계층 구조 사이에서 데이터가 형태를 바꾸며 이동하는 정교한 유체역학적 흐름과 같습니다. 응용 프로그램에서 생성된 데이터는 하위 계층으로 내려가며 각 층의 제어 정보가 덧붙여지는 '추상화의 구체화' 과정을 거칩니다. 이 과정에서 가장 핵심적인 엔지니어링 과제는 어떻게 하면 데이터의 무결성을 유지하면서도, 각 계층이 요구하는 규격에 맞춰 데이터를 효율적으로 분할하고 재조합할 것인가에 있습니다. 전송 매커니즘은 단순한 '이동'이 아니라, 커널 메모리와 네트워크 인터페이스 간의 끊임없는 데이터 복사와 버퍼 관리의 연속입니다.

#### 통신 단위 (PDU)

PDU(Protocol Data Unit)는 특정 계층에서 취급하는 데이터의 논리적 기본 단위를 의미합니다. 각 계층은 상위 계층으로부터 전달받은 데이터(SDU, Service Data Unit)에 자신만의 제어 정보(Header/Trailer)를 결합하여 새로운 PDU를 생성합니다. 이러한 계층별 명칭의 분리는 네트워크 엔지니어가 통신 장애를 분석할 때, 문제가 발생하는 논리적 지점을 정확히 타격할 수 있게 돕는 언어적 도구가 됩니다.

##### 메시지 (Message)

응용 계층에서 생성되는 PDU인 메시지는 데이터의 비즈니스적 의미를 담고 있는 가장 순수한 상태의 정보 덩어리입니다. HTTP 요청 전문, 이메일의 본문, 혹은 파일의 일부가 여기에 해당합니다. 메시지는 크기에 제한이 없으며, 하부 계층의 전송 규격에 구애받지 않는 논리적인 데이터의 집합입니다. 이 단계에서의 데이터 처리는 주로 CPU의 연산 능력과 메모리 대역폭에 의존하며, 데이터의 의미를 해석(Parsing)하고 직렬화(Serialization)하는 과정이 주를 이룹니다.

##### 세그먼트 (Segment)

전송 계층(L4)으로 내려온 데이터는 세그먼트라는 단위로 재구성됩니다. 세그먼트 단계의 핵심은 '포트 번호'를 통한 프로세스 식별과 '순서 번호(Sequence Number)'를 통한 데이터의 조각화 관리입니다. 특히 TCP 환경에서 세그먼트는 MSS(Maximum Segment Size)라는 물리적 제약에 맞춰 잘게 쪼개지며, 각 조각은 수신 측에서 다시 결합될 수 있도록 정교한 인덱싱 정보를 포함합니다. 이 시점부터 데이터는 단순한 정보가 아닌, '흐름 제어'와 '혼잡 제어'의 대상이 되는 관리 품목으로 격상됩니다.

##### 패킷 (Packet)

인터넷 계층(L3)에서는 세그먼트에 논리적 주소인 IP 헤더가 붙어 패킷(또는 IP 데이터그램)이 됩니다. 패킷은 인터넷이라는 거대한 망에서 독립적으로 경로를 찾아갈 수 있는 최소한의 자율 전송 단위입니다. 패킷 헤더에는 발신지와 목적지의 IP 주소뿐만 아니라, 패킷의 수명을 결정하는 TTL(Time To Live)과 상위 프로토콜의 종류를 명시하는 필드가 포함됩니다. 전 세계의 라우터들은 이 패킷의 헤더 정보를 기반으로 넥스트 홉(Next Hop)을 결정하며, 이 과정에서 패킷의 크기가 하부 네트워크의 MTU보다 크다면 추가적인 단편화가 발생할 수 있습니다.

##### 프레임 (Frame)

데이터 링크 계층(L2)의 PDU인 프레임은 물리적인 매체로 송출되기 전의 최종적인 포장 상태입니다. 프레임은 패킷의 앞뒤를 감싸는 '헤더'와 '트레일러'를 가집니다. 특히 트레일러에 포함되는 CRC(Cyclic Redundancy Check)는 물리적 전송 과정에서 발생할 수 있는 비트 오류를 감지하는 강력한 무결성 검증 도구입니다. 프레임은 MAC 주소를 기반으로 인접한 장치 간의 전송을 책임지며, 이더넷 프레임의 경우 1,500바이트라는 표준적인 크기 제한(MTU) 내에서 데이터의 생존을 관리합니다.

##### 비트 (Bit)

물리 계층(L1)에서 데이터는 더 이상 논리적 구조를 갖지 않는 0과 1의 전기적 신호, 즉 비트의 흐름(Bitstream)으로 환원됩니다. 이 단계에서의 PDU는 전압의 고저, 광신호의 유무, 혹은 주파수의 변화 그 자체입니다. 비트 단위의 전송은 하드웨어 트랜시버에 의해 수행되며, 데이터의 의미론적 해석은 완전히 배제된 채 오직 '신호의 재생산'과 '동기화'에만 집중합니다.

#### 데이터 제어 원리

데이터가 계층을 넘나들며 전송되기 위해서는 각 계층의 규격을 준수하는 제어 매커니즘이 필수적입니다. 이는 단순히 정보를 덧붙이는 과정을 넘어, 네트워크 시스템의 성능과 오버헤드 사이의 치열한 트레이드오프를 관리하는 엔지니어링적 의사결정의 연속입니다.

##### 캡슐화 (Encapsulation)

캡슐화는 상위 계층의 데이터(Payload)를 하위 계층 프로토콜의 제어 정보(Header)로 감싸는 과정입니다. 송신측 호스트의 프로토콜 스택을 타고 내려가며 발생합니다. 각 계층은 상위 계층이 준 데이터를 '검은 상자(Opaque Box)'로 취급하며, 그 내부의 내용은 건드리지 않은 채 자신의 제어 정보만을 덧붙입니다.

엔지니어링 관점에서 캡슐화는 메모리 오퍼레이션의 비용을 수반합니다. 운영체제 커널은 패킷 하나를 생성할 때마다 각 계층의 헤더 공간을 확보하기 위해 메모리를 할당하거나, 데이터의 앞부분에 헤더를 복사하는 작업을 수행합니다. Linux 커널의 `sk_buff` 구조체는 이러한 캡슐화 과정에서 발생하는 반복적인 메모리 복사를 최소화하기 위해 헤더를 위한 여유 공간(Headroom)을 미리 확보하는 최적화 전략을 사용합니다.

##### 역캡슐화 (Decapsulation)

역캡슐화는 수신측 호스트에서 캡슐화의 역순으로 진행되는 과정입니다. 물리 계층에서 올라온 비트 스트림을 프레임으로 재구성하고, L2 헤더를 검사한 뒤 떼어내어 상위 계층(L3)으로 전달하는 식입니다. 이 과정은 데이터의 '추출' 단계이며, 각 계층의 소프트웨어 로직은 헤더에 적힌 정보를 바탕으로 패킷이 자신에게 온 것이 맞는지, 오류는 없는지를 검증합니다. 만약 헤더의 정보가 유효하지 않다면, 해당 데이터는 상위 계층으로 전달되지 못하고 그 즉시 폐기됩니다.

##### 페이로드 (Payload)

페이로드는 제어 정보를 제외한, 해당 계층이 운반하고자 하는 '실제 데이터' 그 자체를 의미합니다. 예를 들어, IP 패킷 관점에서의 페이로드는 TCP 세그먼트 전체가 되며, TCP 세그먼트 관점에서의 페이로드는 응용 프로그램이 보낸 메시지 조각이 됩니다. 네트워크의 효율성은 '전체 전송 크기 대비 페이로드의 비중'으로 결정됩니다. 페이로드의 비중이 작을수록 네트워크는 실제 데이터보다 제어 정보를 처리하는 데 더 많은 자원을 낭비하게 되며, 이를 '작은 패킷 문제(Small Packet Problem)'라고 부릅니다.

##### 오버헤드 (Overhead)

오버헤드는 통신을 가능하게 하기 위해 필연적으로 추가되는 '부가적인 비용'입니다. 계층마다 붙는 헤더와 트레일러의 크기, 재전송을 위한 대기 시간, 연결 설정을 위한 핸드쉐이크 패킷 등이 모두 오버헤드에 해당합니다. 

표준적인 TCP/IPv4/Ethernet 환경에서 최소 오버헤드는 프레임당 약 58바이트(이더넷 18B + IP 20B + TCP 20B)에 달합니다. 만약 단 1바이트의 데이터를 보낸다면, 배보다 배꼽이 더 큰 상황이 발생하여 네트워크 효율이 2% 미만으로 급락하게 됩니다. 고성능 시스템 설계자는 이러한 오버헤드를 줄이기 위해 여러 데이터를 하나의 패킷으로 묶어 보내는 '배칭(Batching)'이나, 헤더 크기를 압축하는 기술을 도입하여 유효 처리량(Goodput)을 극대화합니다.

> **Zero-Copy와 오버헤드 최적화**
> 
> 현대의 고성능 서버는 응용 프로그램 메모리에서 커널 메모리로, 다시 NIC 메모리로 데이터가 복사될 때 발생하는 CPU 오버헤드를 극도로 경계합니다. `sendfile()` 시스템 콜과 같은 'Zero-Copy' 기술은 데이터 링크 계층까지 데이터가 복사 없이 직접 전달되도록 설계되어, 캡슐화 과정의 물리적 한계를 극복하려는 시도 중 하나입니다.
{: .block-tip }

### 주소 지정 체계 (Addressing)

네트워크에서 주소는 단순한 식별자를 넘어, 데이터가 이동해야 할 '위치'와 '대상'을 정의하는 논리적 좌표계입니다. 광활한 네트워크 망에서 데이터가 길을 잃지 않고 정확한 프로세스에 도달하기 위해서는 각 계층별로 독립적이면서도 유기적으로 연결된 주소 체계가 필요합니다. 하드웨어에 고정된 물리적 주소부터 가상화된 논리적 주소, 그리고 최종 서비스에 도달하기 위한 관문인 포트 번호에 이르기까지, 주소 지정 체계는 전체 통신 인프라의 신뢰성을 지탱하는 근간이 됩니다.

#### 계층별 식별자

네트워크 스택을 따라 데이터가 흐를 때, 각 계층은 자신만의 언어로 대상을 식별합니다. 이 식별자들은 각기 다른 범위(Scope)와 생명주기를 가지며, 데이터가 하위 계층에서 상위 계층으로 전달될 때마다 식별자의 해상도는 '장치'에서 '망'으로, 다시 '프로세스'로 정밀해집니다.

##### MAC 주소

MAC(Media Access Control) 주소는 데이터 링크 계층(L2)에서 장치를 식별하기 위해 NIC(네트워크 인터페이스 카드) 제작 시점에 할당되는 48비트(6바이트)의 하드웨어 주소입니다. 이는 'Burned-In Address(BIA)'라고도 불리며, 전 세계적으로 유일함을 보장하기 위해 IEEE가 관리하는 OUI(Organizationally Unique Identifier) 24비트와 제조사가 할당하는 24비트의 시리얼 번호로 구성됩니다.

엔지니어링 관점에서 MAC 주소는 '로컬 브로드캐스트 도메인' 내에서의 최종 배달 주소입니다. 스위치는 수신된 프레임의 목적지 MAC 주소를 자신의 MAC 주소 테이블(CAM 테이블)과 대조하여 어떤 포트로 프레임을 송출할지 결정합니다. MAC 주소는 물리적 위치가 변해도 바뀌지 않는 '이름'과 같은 성격을 가지지만, 동일 네트워크 세그먼트를 벗어나는 순간 라우터에 의해 폐기되고 다음 세그먼트의 MAC 주소로 교체되는 특성을 가집니다.

> **MAC 주소 스푸핑과 보안적 한계**
> 
> MAC 주소는 하드웨어에 고정되어 있다고 알려져 있지만, 운영체제의 드라이버 레벨에서 소프트웨어적으로 이를 위조(Spoofing)하는 것이 가능합니다. 이는 보안 인증 수단으로서 MAC 주소 필터링이 가지는 치명적인 취약점이며, 공격자는 이를 이용해 타인의 권한을 획득하거나 중간자 공격(MITM)을 수행할 수 있습니다.
{: .block-warning }

##### IP 주소

IP(Internet Protocol) 주소는 인터넷 계층(L3)에서 사용되는 논리적 식별자로, 데이터가 전 세계 어디에 위치한 네트워크에 속해 있는지를 나타내는 '주소'의 역할을 수행합니다. IPv4 기준 32비트, IPv6 기준 128비트의 길이를 가지며, 하드웨어에 고정된 MAC 주소와 달리 네트워크 관리자나 ISP에 의해 동적으로 변경되거나 재할당될 수 있습니다.

IP 주소의 핵심은 '계층적 구조'에 있습니다. 주소의 앞부분은 네트워크를 식별하는 네트워크 ID, 뒷부분은 해당 네트워크 내의 특정 호스트를 식별하는 호스트 ID로 구분됩니다. 이러한 구조 덕분에 전 세계의 모든 라우터가 모든 장치의 개별 주소를 알 필요 없이, 상위 네트워크 ID만 보고 패킷의 방향을 결정하는 효율적인 '라우팅'이 가능해집니다. 이는 주소 공간의 효율적 관리와 라우팅 테이블의 비대화를 막는 엔지니어링적 해법입니다.

##### 포트 번호 (Port)

포트 번호는 전송 계층(L4)에서 상위 응용 프로그램(프로세스)을 식별하기 위해 사용되는 16비트의 논리적 번호입니다. IP 주소가 특정 컴퓨터(호스트)까지 데이터를 배달한다면, 포트 번호는 그 컴퓨터 안에서 대기 중인 여러 소프트웨어 중 누구에게 데이터를 넘겨줄지 결정합니다. 포트 번호는 0번부터 65535번까지 존재하며, 0~1023번은 시스템 서비스용(Well-known Ports), 1024~49151번은 등록된 서비스용, 그 이후는 동적/사설 포트로 구분됩니다.

운영체제 커널 내부에서는 포트 번호와 IP 주소가 결합된 '소켓(Socket)'이라는 추상화된 인터페이스를 통해 통신이 관리됩니다. 하나의 IP 주소로 여러 클라이언트와 동시에 통신할 수 있는 이유는 'Source IP, Source Port, Destination IP, Destination Port'라는 4개 요소(4-Tuple)의 조합이 매 연결마다 고유하게 생성되기 때문입니다. 이를 포트 다중화(Multiplexing)라고 하며, 이는 현대 서버 시스템이 한정된 자원으로 수천, 수만 개의 동시 접속을 처리할 수 있게 만드는 핵심 매커니즘입니다.

#### 주소 할당 및 확인

주소 지정 체계가 네트워크의 논리적 지도를 그리는 것이라면, 주소 할당 및 확인 매커니즘은 그 지도가 실제 장치와 어떻게 매핑되고 유지되는지를 결정하는 운영의 영역입니다. 단순히 숫자를 부여하는 행위를 넘어, 네트워크의 규모와 유연성, 그리고 관리의 효율성 사이에서 최적의 균형점을 찾는 과정입니다. 특히 가상화와 클라우드 환경이 보편화된 현대 인프라에서는 주소 할당의 자동화와 주소 해석의 정교함이 시스템의 전체 가용성을 좌우하는 핵심 요소로 작용합니다.

##### 정적 할당

정적 할당은 관리자가 장치의 설정 파일이나 운영체제 인터페이스를 통해 IP 주소를 수동으로 명시하는 방식입니다. 엔지니어링 관점에서 정적 할당의 본질은 '예측 가능성'과 '고정성'에 있습니다. 리눅스 시스템의 경우 `/etc/network/interfaces`나 `/etc/netplan/*.yaml`과 같은 설정 파일에 주소가 영구적으로 기록되며, 시스템 부팅 시 커널의 네트워크 스택이 이를 읽어 NIC에 주입합니다.

이 방식은 서버, 라우터, 스위치와 같은 핵심 인프라 장비에서 주로 사용됩니다. 주소가 변하지 않으므로 서비스의 엔드포인트가 고정되며, DNS 서버가 다운되더라도 IP 기반의 직접 통신이 보장된다는 강력한 장점이 있습니다. 그러나 네트워크 규모가 커질수록 관리 오버헤드가 기하급수적으로 증가하며, 주소 충돌(Address Conflict) 시 이를 탐지하고 해결하는 과정이 전적으로 인간의 개입에 의존해야 한다는 치명적인 단점이 있습니다. 또한, 장치의 이동성이 빈번한 환경에서는 정적 할당은 운영의 경직성을 초래하는 병목이 됩니다.

##### 동적 할당 (DHCP)

동적 할당, 특히 DHCP(Dynamic Host Configuration Protocol)는 주소 관리의 자동화를 실현하는 클라이언트-서버 프로토콜입니다. 장치가 네트워크에 접속하는 순간, DHCP 서버로부터 가용한 IP 주소 풀(Pool)에서 하나를 임대(Lease)받는 방식을 취합니다. 이는 단순히 주소뿐만 아니라 서브넷 마스크, 게이트웨이, DNS 서버 정보까지 한 번에 구성할 수 있게 해줍니다.

DHCP의 동작은 'DORA(Discover, Offer, Request, Acknowledgment)'라고 불리는 4단계 프로세스를 통해 이루어집니다. 클라이언트는 먼저 자신의 존재를 알리기 위해 L2 브로드캐스트 패킷(DHCP Discover)을 송출하며, 서버는 이에 응답하여 사용 가능한 주소를 제안(Offer)합니다. 클라이언트가 이를 수락(Request)하면 서버가 최종 확인(ACK)을 보내며 주소 할당이 완료됩니다. 

엔지니어링적으로 DHCP는 '임대 기간(Lease Time)'이라는 개념을 도입하여 한정된 IP 자원을 효율적으로 회수하고 재사용합니다. 그러나 UDP 67/68번 포트를 기반으로 하는 이 과정은 브로드캐스트에 의존하기 때문에, 대규모 네트워크에서는 브로드캐스트 트래픽이 망의 성능을 저하시키는 원인이 되기도 합니다. 이를 방지하기 위해 'DHCP Relay' 기술을 사용하여 브로드캐스트 도메인을 분리하면서도 중앙 집중화된 주소 관리를 수행하는 설계적 기법이 동원됩니다.

##### 루프백 주소 (Loopback)

루프백 주소는 외부 네트워크 매체를 거치지 않고 호스트 자기 자신을 가리키는 가상의 논리적 주소입니다. IPv4에서는 보통 `127.0.0.1`로 정의되며, 운영체제 커널 내부에 `lo` 또는 `lo0`라는 가상 네트워크 인터페이스로 존재합니다.

루프백 주소의 엔지니어링적 가치는 '네트워크 스택 검증'과 '로컬 서비스 격리'에 있습니다. 데이터가 루프백 주소로 송신되면, 커널의 IP 계층은 이를 감지하여 물리적 NIC로 패킷을 내려보내지 않고 즉시 수신 버퍼로 되돌립니다(Loop back). 이를 통해 실제 네트워크 하드웨어 장애 여부와 관계없이 호스트 내부의 TCP/IP 프로토콜 스택이 정상적으로 동작하는지 테스트할 수 있습니다. 또한, 서버 애플리케이션 개발 시 외부 노출 없이 로컬 환경에서만 통신을 수행해야 하는 보안적 요구사항을 충족시키는 안전한 샌드박스 역할을 수행합니다.

##### ARP (주소 확인 프로토콜)

ARP(Address Resolution Protocol)는 논리적 주소인 IP를 물리적 주소인 MAC으로 매핑해주는 핵심 교량 프로토콜입니다. IP 패킷이 목적지 네트워크까지 도달하더라도, 실제 데이터 링크 계층에서 전선을 통해 데이터를 전달하기 위해서는 상대방 NIC의 고유한 MAC 주소를 반드시 알아야 합니다.

동작 원리는 단순하지만 강력합니다. 송신 측은 목적지 IP 주소는 알지만 MAC 주소를 모를 때, "이 IP를 가진 장치는 누구인가?"라는 ARP Request 패킷을 브로드캐스트로 전송합니다. 해당 IP를 가진 장치만이 자신의 MAC 주소를 담아 유니캐스트로 ARP Reply를 보냅니다. 효율성을 위해 운영체제는 한 번 알아낸 매핑 정보를 메모리 내의 'ARP Cache Table'에 일정 시간 동안 저장합니다.

그러나 ARP는 인증 절차가 결여된 설계적 취약점을 가지고 있습니다. 공격자가 거짓 ARP Reply를 지속적으로 보내어 네트워크 트래픽을 가로채는 'ARP Spoofing' 공격에 노출될 수 있으며, 이는 L2 보안 설계 시 반드시 고려해야 할 트레이드오프입니다. 또한, ARP 테이블의 크기가 커지면 검색 속도에 영향을 미치므로, 고성능 장비에서는 정적인 ARP 매핑이나 주기적인 테이블 최적화 로직이 수반됩니다.

> **Gratuitous ARP (GARP)의 활용**
> 
> 요청이 없어도 스스로 자신의 IP와 MAC 정보를 브로드캐스트하는 GARP는 IP 충돌을 감지하거나, 고가용성(HA) 구성에서 마스터 장비가 바뀌었을 때 주변 스위치의 MAC 테이블을 즉시 갱신(Update)하는 중요한 역할을 수행합니다.
{: .block-tip }

### 통신 패러다임 (Paradigm)

네트워크 아키텍처에서 통신 패러다임은 데이터가 전송되는 '방식'과 '범위'를 규정하는 철학적, 기술적 체계를 의미합니다. 단순히 패킷을 보내는 행위를 넘어, 물리적 매체의 자원을 어떻게 분할하여 사용할 것인지(방향성), 그리고 복잡한 망 구조 내에서 어떤 논리로 수신 대상을 식별하고 필터링할 것인지(대상 분류)를 정의합니다. 이러한 패러다임의 선택은 시스템의 처리량(Throughput), 지연 시간(Latency), 그리고 전체적인 네트워크 효율성에 결정적인 영향을 미치며, 설계자는 애플리케이션의 요구사항과 하드웨어 제약 조건 사이에서 가장 적합한 전송 모드를 결정해야 합니다.

#### 전송 방향 모드

전송 방향 모드는 통신 채널을 통해 데이터가 흐를 수 있는 물리적/논리적 경로의 가용성을 분류합니다. 이는 단순히 전선이 몇 가닥인가의 문제를 넘어, 트래픽 경합(Contention)을 처리하는 로직과 송수신 동기화 매커니즘의 차이를 발생시킵니다. 현대 네트워크는 자원의 극대화된 활용을 위해 전이중(Full Duplex) 방식을 지향하지만, 특정 환경이나 하위 호환성을 위해 단방향 혹은 반이중 방식이 여전히 공존하고 있습니다.

##### 단방향 (Simplex)

단방향 통신은 데이터가 오직 한 방향으로만 흐르는 가장 단순하고 원초적인 모드입니다. 송신자는 오직 보내기만 하고, 수신자는 오직 받기만 하는 구조로, 수신 측에서 송신 측으로 어떠한 피드백이나 응답(ACK)도 보낼 수 없는 물리적 절연 상태를 전제로 합니다.

엔지니어링 관점에서 단방향 통신은 채널의 대역폭 전체를 한 방향 전송에만 할당할 수 있다는 특징이 있습니다. 라디오 방송, TV 수신, 혹은 센서에서 중앙 서버로의 일방적인 데이터 덤프 등이 이에 해당합니다. 그러나 오류 제어가 불가능하다는 치명적인 단점이 있습니다. 수신 측에서 패킷 유실이나 비트 오류를 감지하더라도 재전송을 요청할 경로가 없기 때문에, 이를 극복하기 위해 순방향 오류 정정(Forward Error Correction, FEC)과 같은 고도의 중복 데이터 전송 기법이 동반되어야 합니다. 이는 대역폭의 일부를 오류 정정에 할당해야 하는 효율성의 트레이드오프를 발생시킵니다.

##### 반이중 (Half Duplex)

반이중 통신은 양방향 통신이 가능하지만, 동시에 양방향으로 데이터를 보낼 수는 없는 방식입니다. 하나의 물리적 채널을 송신과 수신이 시간적으로 분할하여 공유하므로, 특정 시점에는 오직 한 쪽만 데이터를 송출할 수 있습니다.

전통적인 허브(Hub) 기반의 이더넷이나 무선 LAN(Wi-Fi), 그리고 무전기 통신이 반이중 모드의 전형입니다. 이 모드의 핵심 엔지니어링 과제는 '충돌(Collision)' 관리입니다. 두 장치가 동시에 데이터를 보내려 할 때 신호가 겹쳐 데이터가 파괴되는 현상을 막기 위해 CSMA/CD(유선)나 CSMA/CA(무선)와 같은 매체 접근 제어 알고리즘이 필수적으로 동작합니다. 충돌이 발생하면 지수적 백오프(Exponential Backoff) 알고리즘에 따라 임의의 시간 동안 대기 후 재전송을 시도하게 되는데, 이는 네트워크 부하가 증가할수록 지연 시간이 급격히 늘어나는 성능 저하의 원인이 됩니다.

##### 전이중 (Full Duplex)

전이중 통신은 송신과 수신이 독립적인 경로를 통해 동시에 이루어지는 현대 네트워크의 표준적 전송 모드입니다. 물리적으로 송신용 선로와 수신용 선로가 분리되어 있거나, 하나의 선로 내에서 주파수 분할(FDM) 혹은 시분할(TDM) 기술을 통해 논리적으로 완벽히 격리된 두 개의 통로를 확보한 상태를 의미합니다.

현대 스위치(Switch) 기반 이더넷 환경은 전이중 모드를 기본으로 합니다. 충돌 발생 가능성이 원천적으로 차단되므로 CSMA/CD와 같은 경합 매커니즘이 필요 없으며, 이는 대역폭 효율을 반이중 대비 이론적으로 2배 이상 향상시킵니다. 엔지니어링 측면에서 전이중 모드는 송신 버퍼와 수신 버퍼를 완전히 독립적으로 운영할 수 있게 하여, 데이터가 흐르는 동안 동시에 제어 정보(ACK)를 주고받는 '피기배킹(Piggybacking)' 기술을 가능케 합니다. 이는 TCP의 처리량(Throughput)을 극대화하는 데 결정적인 기여를 합니다.

> **전이중 모드에서의 성능과 큐잉(Queuing)**
> 
> 전이중 모드는 충돌은 없지만, '버퍼 넘침(Buffer Overflow)'이라는 새로운 문제에 직면합니다. 양방향에서 데이터가 쏟아져 들어올 때 스위치나 호스트의 메모리 내 수신 큐(Queue)가 가득 차면 패킷 드롭이 발생합니다. 이를 관리하기 위해 이더넷 일시 중지 프레임(Pause Frame)과 같은 흐름 제어 매커니즘이 L2 레벨에서 동작하게 됩니다.
{: .block-tip }

#### 전송 대상 분류 (Cast)

전송 대상 분류는 네트워크상에서 패킷의 '수신 범위'를 어떻게 규정할 것인가에 대한 공학적 방법론입니다. 단순히 데이터를 보내는 주소의 개수를 넘어, 네트워크 인터페이스 카드(NIC)의 필터링 로직, 커널의 인터럽트 처리 방식, 그리고 라우팅 테이블의 경로 계산 메커니즘이 이 분류에 따라 완전히 다르게 작동합니다. 설계자는 네트워크의 혼잡도와 통신 효율성을 고려하여 유니캐스트, 브로드캐스트, 멀티캐스트, 애니캐스트 중 가장 적합한 전송 패러다임을 선택해야 합니다.

##### 유니캐스트 (Unicast)

유니캐스트는 특정 송신자와 특정 수신자 간의 1:1 통신 방식입니다. 인터넷 트래픽의 대다수를 차지하며, 목적지 MAC 주소와 IP 주소가 단 하나의 인터페이스만을 가리키도록 설정됩니다.

엔지니어링 관점에서 유니캐스트의 핵심은 '효율적 필터링'에 있습니다. 데이터 링크 계층에서 NIC는 유입되는 프레임의 목적지 MAC 주소를 확인합니다. 만약 자신의 MAC 주소와 일치하지 않는다면, NIC는 해당 데이터를 즉시 폐기(Drop)하며 호스트 CPU에 인터럽트를 발생시키지 않습니다. 이는 시스템 자원을 보호하는 중요한 하드웨어적 방어 기법입니다. 그러나 유니캐스트는 동일한 데이터를 여러 명에게 보내야 할 경우, 수신자 수만큼 패킷을 복사하여 전송해야 하므로 송신자의 대역폭 소모가 수신자 수(N)에 비례하여 선형적으로 증가한다는 트레이드오프를 가집니다.

##### 브로드캐스트 (Broadcast)

브로드캐스트는 동일한 네트워크 세그먼트 내의 모든 호스트에게 데이터를 전송하는 1:All 방식입니다. 목적지 MAC 주소는 `FF:FF:FF:FF:FF:FF`로, IP 주소는 해당 네트워크의 최댓값(예: `255.255.255.255`)으로 고정됩니다.

브로드캐스트의 치명적인 엔지니어링 비용은 '모든 호스트의 강제적 참여'에 있습니다. 네트워크 내의 모든 NIC는 브로드캐스트 프레임을 수락하도록 설계되어 있으며, 이는 모든 호스트의 커널에 인터럽트를 발생시켜 CPU가 해당 패킷을 처리하게 강제합니다. 만약 불필요한 브로드캐스트 트래픽이 과도하게 발생하면, 네트워크상의 모든 장치가 데이터 처리로 인해 성능이 저하되는 '브로드캐스트 스톰(Broadcast Storm)' 현상이 발생할 수 있습니다. 이러한 이유로 브로드캐스트는 라우터에 의해 차단되며, 오직 로컬 네트워크(L2 도메인) 내에서만 유효하게 작동합니다.

##### 멀티캐스트 (Multicast)

멀티캐스트는 특정 그룹에 가입된 호스트들에게만 데이터를 전송하는 1:Group(N) 방식입니다. IPv4에서는 클래스 D(224.0.0.0/4) 주소 대역을 사용하여 논리적인 그룹을 식별합니다.

멀티캐스트의 공학적 정수는 '네트워크 인프라의 지능적 복제'에 있습니다. 송신자는 데이터를 단 한 번만 송출하며, 경로상의 스위치와 라우터가 그룹 멤버십(IGMP 등)을 확인하여 데이터가 필요한 지점에서만 패킷을 복제합니다. 이를 통해 송신자의 대역폭 부하를 혁신적으로 줄이면서 대규모 수신자에게 고화질 영상을 스트리밍하거나 증권 시세 데이터를 전송할 수 있습니다. 하지만 멀티캐스트를 구현하기 위해서는 네트워크 장비가 IGMP Snooping과 같은 복잡한 프로토콜을 지원해야 하며, UDP 기반으로 동작하기 때문에 신뢰성(재전송) 보장을 위해서는 애플리케이션 레벨에서의 추가적인 설계가 필요합니다.

##### 애니캐스트 (Anycast)

애니캐스트는 동일한 IP 주소를 전 세계 여러 지점에 할당하고, 라우팅 프로토콜(BGP)에 의해 송신자로부터 '가장 가까운(Shortest Path)' 수신자에게 패킷을 전달하는 방식입니다.

애니캐스트의 본질은 '네트워크 수준의 로드 밸런싱'과 '고가용성'입니다. 주로 DNS 서버나 CDN(Content Delivery Network) 에지 서버 구성에 사용됩니다. 특정 서버에 장애가 발생하여 라우팅 광고가 중단되면, 네트워크는 자동으로 다음으로 가까운 정상 서버로 트래픽을 유도합니다. 

> **애니캐스트와 TCP의 충돌 가능성**
> 
> 애니캐스트는 상태가 없는(Stateless) UDP 통신에 최적화되어 있습니다. TCP의 경우, 통신 도중 네트워크 경로가 변하여 패킷이 다른 애니캐스트 노드로 전달되면 해당 노드에는 기존의 세션 정보(TCP State)가 없으므로 연결이 즉시 끊어지는 현상이 발생할 수 있습니다. 이를 극복하기 위해 정교한 경로 유지 알고리즘이나 짧은 수명의 연결 세션 설계가 요구됩니다.
{: .block-warning }

## 네트워크 구조 및 연결 (Topology)

네트워크 토폴로지는 노드와 링크가 배치되는 기하학적 형상을 넘어, 데이터가 흐르는 '물리적 통로'와 '논리적 제어 경로'의 설계 양식을 의미합니다. 토폴로지의 선택은 단순한 설치의 편의성을 넘어, 시스템의 장애 내성(Fault Tolerance), 확장성(Scalability), 그리고 배선 비용(Cabling Cost) 사이의 복잡한 엔지니어링적 절충안을 결정합니다. 물리적 토폴로지가 실제 케이블의 연결 형태를 정의한다면, 논리적 토폴로지는 데이터가 장치 간에 어떻게 전달되는지(예: 브로드캐스트 도메인의 범위)를 규정하며, 현대 네트워크에서는 물리적으로는 성형(Star)이지만 논리적으로는 버스(Bus)나 망형(Mesh)으로 동작하는 하이브리드 구조가 보편화되어 있습니다.

### 물리적/논리적 구조

물리적 구조는 케이블, 커넥터, 장치의 하드웨어적 배치를 다루며, 논리적 구조는 그 하드웨어 위에서 신호가 흐르는 규칙을 다룹니다. 이 두 구조의 괴리를 이해하는 것은 네트워크 트러블슈팅의 핵심입니다. 예를 들어, 하나의 스위치에 모든 호스트가 연결된 물리적 성형 구조에서, 스위치 내부의 백플레인(Backplane) 로직에 따라 데이터는 특정 포트로만 흐르는 전이중 유니캐스트(논리적 전이중) 혹은 모든 포트로 복제되는 브로드캐스트(논리적 버스) 형태를 띠게 됩니다.

##### 성형 (Star)

성형 토폴로지는 모든 노드가 중앙의 제어 장치(Hub, Switch)에 개별적으로 연결된 방사형 구조입니다. 현대 LAN 환경의 표준이라 할 수 있는 이 구조는 관리의 중앙 집중화와 장애 격리에 탁월한 성능을 발휘합니다.

엔지니어링 관점에서 성형 구조의 최대 장점은 '장애 국소화'입니다. 특정 노드와 중앙 장치 사이의 케이블이 단선되더라도 나머지 노드들은 통신에 지장을 받지 않습니다. 하지만 중앙 장치 자체가 '단일 장애점(Single Point of Failure, SPoF)'이 된다는 치명적인 약점이 존재합니다. 중앙 스위치의 하드웨어 장애나 전원 공급 중단은 연결된 모든 노드의 통신 마비를 초래합니다. 이를 방지하기 위해 엔터프라이즈 환경에서는 스위치를 이중화(Redundancy)하거나 스택킹(Stacking) 기술을 통해 논리적인 하나의 거대 스위치를 구성하여 가용성을 확보합니다.

##### 망형 (Mesh)

망형 토폴로지는 모든 노드가 다른 모든 노드와 전용 링크로 직접 연결되는 구조입니다. 가능한 모든 경로가 사전에 연결되어 있으므로, 이론적으로 가장 높은 수준의 가용성과 신뢰성을 제공합니다.

완전 망형(Full Mesh) 구조에서 필요한 링크의 수는 노드의 개수가 $n$일 때 $\frac{n(n-1)}{2}$로 결정됩니다. 이는 노드 수가 증가함에 따라 배선 비용과 포트 소모량이 기하급수적으로 늘어남을 의미합니다. 이러한 비용 문제로 인해 실제 환경에서는 핵심 노드들만 다중 연결하는 부분 망형(Partial Mesh)이 주로 사용됩니다. 망형 구조는 주 경로에 장애가 발생하더라도 대체 경로를 즉시 활용할 수 있어, 백본망이나 데이터 센터 내부의 고가용성 서버 군에서 핵심적인 설계 양식으로 채택됩니다.

> **망형 구조와 라우팅 프로토콜**
> 
> 망형 구조에서는 동일 목적지에 대해 다수의 경로가 존재하므로, 어떤 경로가 최적인지 판단하는 라우팅 알고리즘(OSPF, IS-IS 등)의 역할이 매우 중요해집니다. 경로 변화 시 빠르게 수렴(Convergence)하는 능력이 네트워크 전체의 안정성을 결정합니다.
{: .block-tip }

##### 트리형 (Tree)

트리형 토폴로지는 성형 구조를 계층적으로 확장한 형태로, '계층형(Hierarchical) 토폴로지'라고도 불립니다. 최상위의 루트 노드에서 시작하여 여러 단계의 분기점을 거쳐 하위 노드로 연결되는 구조입니다.

엔지니어링 측면에서 트리형 구조는 대규모 네트워크의 체계적인 관리를 가능케 합니다. Core 계층(고속 전송), Aggregation 계층(정책 및 필터링), Access 계층(단말 연결)으로 분리된 3계층 설계 모델은 트리 토폴로지의 논리적 결정체입니다. 하위 분기에서 발생한 트래픽을 상위에서 집계(Aggregation)함으로써 전체 망의 대역폭 효율을 높일 수 있습니다. 하지만 상위 노드로 올라갈수록 트래픽이 집중되므로 병목 현상(Bottleneck)이 발생하기 쉬우며, 상위 노드의 장애는 하부의 서브트리 전체에 영향을 미치는 계층적 장애 확산의 위험을 내포합니다.

##### 버스형 (Bus)

버스형 토폴로지는 하나의 공통 전송 매체(Backbone)에 모든 노드가 공유기 형태로 연결된 구조입니다. 초창기 이더넷(10Base2, 10Base5)에서 사용되었으며, 구조가 단순하고 케이블 소모량이 적다는 경제적 이유로 널리 쓰였습니다.

버스형의 근본적인 한계는 '공유 매체 경합'에 있습니다. 모든 노드가 하나의 선로를 공유하므로, 한 번에 단 하나의 노드만 데이터를 보낼 수 있습니다(반이중 통신). 이를 위해 CSMA/CD 알고리즘이 필수적으로 동작하며, 노드 수가 늘어날수록 충돌(Collision) 확률이 증가하여 실질 처리량이 급격히 감소합니다. 또한, 공통 케이블의 어느 한 지점이라도 단선되거나 종단 저항(Terminator)에 문제가 생기면 전체 네트워크가 마비되는 구조적 취약점을 가집니다. 현대의 유선 네트워크에서는 거의 사라졌으나, 전력선 통신(PLC)이나 특정 산업용 제어망에서 그 흔적을 찾을 수 있습니다.

### 네트워크 범위 분류

네트워크는 물리적 도달 거리와 관리 주체에 따라 PAN, LAN, WAN으로 분류됩니다. 이 분류는 단순히 거리를 나타내는 지표를 넘어, 사용되는 전송 매체, 프로토콜의 특성, 그리고 허용되는 지연 시간(Latency)의 임계치를 결정하는 설계 기준이 됩니다.

##### PAN (Personal)

PAN(Personal Area Network)은 개인을 중심으로 10m 이내의 초단거리 공간에서 동작하는 네트워크입니다. 스마트폰, 스마트워치, 무선 이어폰 등 개인 휴대 기기 간의 데이터 교환이 주 목적입니다.

엔지니어링 관점에서 PAN은 '저전력'과 '동적 구성'에 최적화되어 있습니다. Bluetooth, Zigbee, NFC와 같은 프로토콜이 대표적이며, 기기가 수시로 네트워크에 들어오고 나가는 환경을 고려하여 복잡한 핸드쉐이크보다는 빠르고 간결한 연결 수립 메커니즘을 가집니다. PAN은 통신 범위가 좁아 보안성이 상대적으로 높지만, 다른 무선 기기와의 주파수 간섭(Interference)에 취약하다는 트레이드오프가 존재합니다.

##### LAN (Local)

LAN(Local Area Network)은 사무실, 건물, 가정 등 비교적 좁은 지리적 구내에서 형성되는 고속 네트워크입니다. 전송 매체와 장비를 사용자가 직접 소유하고 관리한다는 점이 특징입니다.

LAN의 핵심은 '고대역폭'과 '저지연'입니다. 일반적으로 1Gbps에서 100Gbps에 이르는 높은 전송 속도를 제공하며, 전파 지연(Propagation Delay)이 매우 낮아 응답 속도가 빠릅니다. 이더넷(IEEE 802.3)과 Wi-Fi(IEEE 802.11)가 주도하는 LAN 환경은 오류 발생률이 낮고 운영 체제의 커널이 네트워크 입출력을 처리하는 오버헤드가 상대적으로 크게 느껴질 정도로 하드웨어 성능이 우수합니다.

##### WAN (Wide)

WAN(Wide Area Network)은 국가나 대륙과 같이 광범위한 지리적 영역을 연결하는 네트워크입니다. LAN과 LAN을 연결하며, 주로 통신 사업자(ISP)가 제공하는 전용선이나 공중망 인프라를 임대하여 사용합니다.

엔지니어링 측면에서 WAN은 LAN과 전혀 다른 도전에 직면합니다. 물리적 거리가 멀기 때문에 빛의 속도 한계에 의한 전파 지연이 무시할 수 없는 수준(수십~수백 ms RTT)으로 발생합니다. 또한, 전송 경로가 복잡하고 중간 장비가 많아 패킷 손실률이 LAN보다 높습니다. 따라서 WAN 환경의 프로토콜은 지연을 최소화하기 위한 윈도우 스케일링(Window Scaling)이나 오류 복구를 위한 정교한 알고리즘이 필수적으로 요구됩니다. 라우팅 기술의 정점인 BGP(Border Gateway Protocol)는 이러한 광범위한 WAN 환경에서 최적의 경로를 결정하는 인터넷의 이정표 역할을 수행합니다.

> **LAN과 WAN의 경계 붕괴**
> 
> 과거에는 속도와 거리로 LAN과 WAN을 명확히 구분했으나, 광통신 기술의 발달로 WAN 구간에서도 Gbps급 속도가 보편화되면서 그 경계가 모호해지고 있습니다. 다만, '관리 주체가 누구인가'와 '지연 시간의 물리적 한계'는 여전히 두 네트워크를 구분하는 중요한 공학적 척도입니다.
{: .block-warning }
