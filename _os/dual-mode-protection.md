### 이중 모드와 보호

운영체제는 여러 프로그램이 동시에 실행되는 환경에서, 특정 프로그램의 오류나 악의적인 공격이 시스템 전체를 붕괴시키지 않도록 방지해야 한다. 이를 위해 하드웨어 차원에서 적어도 두 가지 이상의 독립적인 동작 모드를 지원해야 하는데, 이를 **이중 모드(Dual Mode)**라고 한다.



#### 사용자 모드 (User Mode) vs 커널 모드 (Kernel Mode)

CPU는 현재 실행 중인 코드가 운영체제 코드인지, 사용자 애플리케이션 코드인지 구분하여 권한을 차등 부여한다.

- **사용자 모드 (User Mode, bit 1):** 제한된 명령만 수행할 수 있는 모드다. 우리가 작성한 대부분의 애플리케이션 코드는 이 모드에서 실행된다. 하드웨어에 직접 접근하거나 시스템의 중요한 설정을 변경할 수 없다.
- **커널 모드 (Kernel Mode, bit 0):** 시스템의 모든 메모리와 모든 CPU 명령에 접근할 수 있는 강력한 권한을 가진다. '시스템 모드', '특권 모드(Privileged Mode)'라고도 불린다.

#### 모드 비트 (Mode Bit)

하드웨어는 현재 어떤 모드에서 실행 중인지를 나타내기 위해 CPU 내부의 상태 레지스터(Status Register)에 **모드 비트(Mode Bit)**를 둔다.

- **비트 값의 의미:** 일반적으로 커널 모드는 `0`, 사용자 모드는 `1`로 설정된다.
- **동작 원리:**
    1. 사용자 애플리케이션 실행 중 (Mode Bit = 1).
    2. 애플리케이션이 운영체제 서비스를 요청(System Call)하거나 인터럽트가 발생.
    3. 하드웨어는 트랩(Trap)을 발생시키며 모드 비트를 `0`으로 변경하고, 제어권을 OS의 핸들러로 넘김.
    4. OS가 작업을 마치면 사용자 프로그램으로 복귀하기 위해 `Return from Interrupt` 명령을 수행.
    5. 이 명령이 수행될 때 하드웨어는 모드 비트를 다시 `1`로 변경.

#### 특권 명령 (Privileged Instructions)

시스템의 안전을 해칠 우려가 있는 명령은 **오직 커널 모드에서만 실행**할 수 있도록 하드웨어가 통제한다. 이를 특권 명령이라 한다.

**주요 특권 명령:**

- **I/O 장치 제어:** 디스크 읽기/쓰기, 네트워크 패킷 전송 등.
- **메모리 관리:** 기준 레지스터(Base Register)나 한계 레지스터(Limit Register) 값 변경, 페이지 테이블 수정.
- **인터럽트 제어:** 인터럽트 활성화/비활성화 (Turn off interrupts).
- **모드 변경:** 사용자 모드에서 커널 모드로의 임의 전환.

> 만약 사용자 모드에서 특권 명령을 실행하려고 시도하면 어떻게 될까?
> CPU는 이를 실행하지 않고 즉시 **"불법 명령 예외(Illegal Instruction Exception)"**를 발생시켜 운영체제에 알린다. OS는 해당 프로세스를 강제 종료(Kill)시킨다.

#### 메모리 보호 (Memory Protection)

이중 모드만으로는 부족하다. 어떤 사용자 프로세스가 다른 프로세스의 메모리나 OS의 커널 영역을 침범하지 못하도록 막아야 한다. 이를 위해 하드웨어는 두 개의 레지스터를 사용한다.

- **기준 레지스터 (Base Register):** 프로세스가 접근할 수 있는 가장 작은 물리 메모리 주소.
- **한계 레지스터 (Limit Register):** 기준 레지스터로부터의 범위(크기).

CPU는 사용자 모드에서 생성되는 모든 메모리 접근 주소가 `Base <= 주소 < Base + Limit` 범위 내에 있는지 하드웨어적으로 검사한다. 범위를 벗어나면 **메모리 보호 오류(Memory Protection Fault)** 트랩을 발생시킨다.

#### [Practice] Memory Protection in Action

이론에서 배운 "사용자 모드는 커널 영역이나 허용되지 않은 메모리에 접근할 수 없다"는 원칙이 실제로 어떻게 작동하는지 확인해 본다. C언어를 사용하여 의도적으로 **NULL 포인터(0x0 번지)**에 값을 쓰려고 시도한다.

##### 1. 검증 코드 (C Language)

포인터를 사용하여 프로세스에게 할당되지 않은 메모리 주소(0x0)를 가리키게 하고, 그곳에 데이터를 덮어쓰는 위험한 코드를 작성해보자.

```c
#include <stdio.h>

int main() {
    printf("Attempting to write to kernel memory (0x0)...\n");

    // 1. 포인터를 강제로 0번지(NULL)로 설정
    // 0번지는 통상적으로 운영체제 커널을 위해 예약되어 있거나,
    // 오류 검출을 위해 접근이 차단된(No Access) 영역이다.
    int *forbidden_addr = (int *)0x0;

    // 2. 해당 주소에 값 쓰기 시도 (Dereference)
    // 이 시점에 하드웨어(MMU)가 접근 위반을 감지하고 Trap을 발생시킨다.
    *forbidden_addr = 100; 

    // 프로세스는 위 라인에서 강제 종료되므로, 이 메시지는 출력되지 않는다.
    printf("This line will never be printed.\n");

    return 0;
}
```

##### 2. 실행 결과 및 해석

코드를 컴파일하고 실행하면 운영체제는 즉시 프로세스를 종료시킨다.

```text
Attempting to write to kernel memory (0x0)...
Segmentation fault (core dumped)
```

1.  **하드웨어의 감시:** CPU는 데이터를 메모리에 쓰려는 명령(`*ptr = 100`)을 실행하기 전, 해당 주소가 현재 프로세스의 **Base/Limit 레지스터** 범위 내에 있는지, 혹은 **페이지 테이블** 권한에 맞는지 검사한다.
2.  **트랩 발생:** `0x0` 번지는 사용자 프로세스에게 쓰기 권한이 없는 영역이다. 하드웨어(MMU)는 즉시 **예외(Exception)**를 발생시켜 CPU 제어권을 운영체제 커널로 넘긴다.
3.  **OS의 처분:** 커널의 트랩 핸들러는 이 예외가 "유효하지 않은 메모리 접근"임을 확인하고, 해당 프로세스에게 `SIGSEGV` 시그널을 보내 **강제 종료(Kill)** 시킨다. 이것이 우리가 흔히 보는 `Segmentation fault`의 정체이다.

> **백엔드 관점: I/O 버퍼링과 모드 전환 비용**
>
> 백엔드 성능 튜닝에서 "시스템 콜을 줄여라"라는 말이 나오는 기술적 근거가 바로 이중 모드에 있다.
>
> 1. **Context Switching 비용:** `User Mode`에서 `Kernel Mode`로 넘어가기 위해서는 현재 CPU 레지스터 상태를 저장하고, TLB(Translation Lookaside Buffer)를 플러시(Flush)하는 등의 오버헤드가 발생한다. 이는 단순한 함수 호출(Function Call)보다 수십~수백 배 느리다.
> 2. **Buffered I/O의 필연성:** Java의 `FileInputStream`에서 `read()`를 호출하면 1바이트를 읽기 위해 시스템 콜을 수행한다. 1GB 파일을 1바이트씩 읽는다면 10억 번의 모드 전환(User <-> Kernel)이 발생하여 시스템은 마비될 것이다.
> 3. **해결책:** `BufferedInputStream`이나 `BufferedReader`는 내부적으로 8KB 정도의 메모리 버퍼를 둔다. `read()`를 호출해도 실제 시스템 콜은 8KB가 다 찰 때까지 발생하지 않거나, 한 번의 시스템 콜로 8KB를 미리 왕창 읽어온다. 즉, **값비싼 모드 전환 횟수를 획기적으로 줄이는 것**이 버퍼링의 본질이다.
